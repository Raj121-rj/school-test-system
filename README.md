# स्कूल टेस्ट एवं विश्लेषण प्रणाली — सत्र 2026–27

कक्षा **5, 8, 10, 12** के लिए एक पूरी **वेबसाइट**: Login → Admin / Teacher / Student dashboard → PostgreSQL डेटाबेस।
टेस्ट कागज़ पर (offline) होते हैं; वेबसाइट सिर्फ़ **निर्धारित टेस्ट-कैलेंडर, अंक-प्रविष्टि और विश्लेषण** संभालती है। प्रश्न-पत्र वेबसाइट पर नहीं बनते।

* **192 टेस्ट** (4 कक्षाएँ × 48 तारीखें, 12 अक्टूबर 2026 – 15 फ़रवरी 2027) आपकी Master Calendar Excel से सीधे डेटाबेस में लोड होते हैं (`data/master_calendar.json`)।
* **335 अध्याय** (21 विषय) — हर टेस्ट अपने अध्यायों से जुड़ा है, इसलिए अध्यायवार विश्लेषण मिलता है।
* अंक ही **एकमात्र स्रोत** हैं: औसत, रुझान, रैंकिंग आदि हर बार अंकों से गिने जाते हैं, अलग से सेव नहीं होते।

## 2. तकनीक (सरल और भरोसेमंद)

* **Node.js** (≥ 18) — कोई web-framework नहीं; सिर्फ़ दो dependencies: `pg` (PostgreSQL) और `exceljs` (Excel)।
* **PostgreSQL** — सारा डेटा; `src/schema.sql` हर स्टार्ट पर सुरक्षित रूप से चलती है।
* **Frontend** — साधारण HTML/CSS/JavaScript (`public/`), कोई build-step नहीं; मोबाइल और कंप्यूटर दोनों पर चलता है।
* एक ही Node सर्विस पूरी वेबसाइट (पेज + API) चलाती है, इसलिए Render पर एक Web Service + एक PostgreSQL काफ़ी है।

```
server.js              सर्वर शुरू करता है (migrate → seed → listen)
src/schema.sql         डेटाबेस तालिकाएँ
src/seed.js            पहली बार: कक्षाएँ, विषय, अध्याय, 192 टेस्ट, अवकाश, Admin, (वैकल्पिक) डेमो
src/routes/*.js        API: auth, people, tests, analysis, dashboard, admin
src/analytics.js       विश्लेषण का गणित (शुद्ध functions, टेस्ट किए हुए)
src/calendar.js        Calendar Excel पढ़ना + सिलेबस → अध्याय मिलान
src/importer.js        विद्यार्थी Excel की जाँच
public/                वेबसाइट के पेज
data/                  master_calendar.json, chapters.json
scripts/check.js       deploy से पहले की जाँच;  scripts/reset-admin.js  पासवर्ड भूलने पर
tests/                 स्वचालित टेस्ट
```

## 3. Render पर deploy (सबसे आसान: Blueprint)

1. यह पूरा फ़ोल्डर **GitHub** पर एक नई (private) repository में डालें (`node_modules` नहीं, `.gitignore` पहले से है)।
2. Render Dashboard → **New → Blueprint** → अपनी repository चुनें। Render `render.yaml` पढ़कर **Web Service + PostgreSQL** बनाएगा।
3. पूछे जाने पर **`ADMIN_PASSWORD`** लिखें (कम से कम 8 अक्षर)। `JWT_SECRET` और `DATABASE_URL` अपने-आप भरते हैं।
4. **Apply** दबाएँ। पहला build/deploy 3–6 मिनट लेता है। Logs में `[setup] Master Calendar लोड हुआ: 192 टेस्ट` और `[ready]` दिखना चाहिए।
5. Render का URL (जैसे `https://school-test-system.onrender.com`) खोलें → **/login** → `admin` + आपका `ADMIN_PASSWORD`।
6. अपना अपना डोमेन चाहिए तो Service → Settings → **Custom Domains**।

**Plans:** `render.yaml` में Web `starter` और Database `basic-256mb` (paid) रखे हैं — असली स्कूल-डेटा के लिए यही ठीक है।
ट्रायल के लिए दोनों `plan: free` कर सकते हैं, पर **free PostgreSQL ~30 दिन बाद expire होकर मिट जाता है** (14 दिन का grace) और free Web Service निष्क्रियता पर सो जाती है।

**बिना Blueprint (manual):** New → PostgreSQL बनाएँ (Internal Database URL कॉपी करें) → New → Web Service (वही repo): Build `npm install --omit=dev && npm run check`, Start `node server.js`, Health Check `/healthz`; Environment में `NODE_ENV=production`, `DATABASE_URL`, `JWT_SECRET` (लंबा random), `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SCHOOL_TZ=Asia/Kolkata`, `SEED_DEMO=true`।

## 4. पहली बार का setup (क्रम से)

1. **Admin → सेटिंग्स:** विद्यालय का नाम भरें; "ध्यान चाहिए" का % (डिफ़ॉल्ट 40) देखें।
2. **Admin → टेस्ट कैलेंडर → "पूर्णांक और समय सेट करें":** आपकी Excel में पूर्णांक/समय नहीं थे, इसलिए वहाँ से एक साथ भरें (बाद में हर टेस्ट अलग से बदल सकते हैं)। *जब तक पूर्णांक न हो, अंक भरे नहीं जा सकते।*
3. **Admin → शिक्षक:** शिक्षक जोड़ें → **कक्षा/विषय सौंपें**। पासवर्ड सिर्फ़ एक बार दिखता है — लिख लें/डाउनलोड करें।
4. **Admin → विद्यार्थी इम्पोर्ट:** कक्षा चुनें → टेम्पलेट → भरकर अपलोड → जाँच देखें → पुष्टि। हर विद्यार्थी के लॉगिन की सूची (CSV) डाउनलोड करके बाँटें। पहले लॉगिन पर विद्यार्थी अपना पासवर्ड बदलता है।
5. **डेमो डेटा हटाएँ:** पहले से `SEED_DEMO=true` है, इसलिए डेमो शिक्षक/विद्यार्थी/अंक बन गए होंगे। असली उपयोग शुरू करने से पहले **Admin → सेटिंग्स → "डेमो डेटा हटाएँ"** (DELETE लिखकर)। फिर Render में `SEED_DEMO` को `false` कर दें।

**डेमो खाते (SEED_DEMO=true पर):** शिक्षक `teacher1` / `Teacher@123`; विद्यार्थी `st00001`, `st00002`, … / `Student@123`; Admin = आपका `ADMIN_USERNAME` / `ADMIN_PASSWORD`।

**Admin का पासवर्ड भूल गए?** Render → Service → **Shell**: `node scripts/reset-admin.js "नया-पासवर्ड123"`

## 5. टेस्ट का रोज़ का काम

शिक्षक लॉगिन → **अंक प्रविष्टि** (बाकी टेस्ट सबसे पहले) → टेस्ट खोलें (सिलेबस/अध्याय ऊपर दिखते हैं) → अंक भरें → **सेव (प्रगति)** → सब भरने पर **अंतिम जमा + लॉक**।
लॉक के बाद विद्यार्थी को अंक दिखने लगते हैं और विश्लेषण में गिने जाते हैं। सुधार सिर्फ़ Admin कर सकता है (कारण ज़रूरी)।
विद्यार्थी को **सिर्फ़ लॉक किए (अंतिम) अंक** दिखते हैं — अधूरी प्रविष्टि नहीं।

## 6. विश्लेषण की परिभाषाएँ

* **प्रतिशत** = प्राप्तांक ÷ पूर्णांक × 100। अनुपस्थित टेस्ट औसत में नहीं गिना जाता (अलग गिना जाता है)।
* **हुए टेस्ट** = जिन टेस्ट में अंक दर्ज/लॉक हैं (रद्द/स्थगित नहीं)।
* **प्रवृत्ति (सुधार / स्थिर / गिरावट):** कम से कम **4 टेस्ट** चाहिए, वरना "डेटा कम" दिखता है। हाल के (अधिकतम 3) टेस्ट के औसत की तुलना उससे पहले के उतने ही टेस्ट से होती है; **±5 प्रतिशत-अंक** से ज़्यादा फ़र्क = सुधार/गिरावट। यही अंतर "सुधार %" है।
* **ध्यान चाहिए:** औसत सेटिंग्स के % से कम (कम से कम 2 टेस्ट के बाद), या गिरावट ≥ 10 अंक, या 3+ टेस्ट में अनुपस्थित।
* **शीर्ष प्रदर्शन:** औसत के अनुसार, न्यूनतम टेस्ट (सेटिंग्स, डिफ़ॉल्ट 3) दिए हुए विद्यार्थी।
* **अध्याय का स्कोर** = उन सभी टेस्ट का औसत जिनमें वह अध्याय शामिल था ("पूर्ण पाठ्यक्रम" टेस्ट अध्याय में नहीं गिने जाते)।
* Teacher को विश्लेषण/रिपोर्ट में सिर्फ़ **अपने सौंपे विषयों** के अंक दिखते हैं।

## 7. Excel फ़ॉर्मैट

* **विद्यार्थी:** `Roll No. | Student Name | Father Name | Mother Name | DOB | Gender` (DOB: `YYYY-MM-DD` या `DD-MM-YYYY`; Gender: M/F)। केवल `.xlsx`।
* **Master Calendar:** `क्रम | तारीख | दिन | कक्षा | टेस्ट नं. | विषय | सिलेबस/अध्याय | टेस्ट प्रकार` (वैकल्पिक: पूर्णांक, समय, स्थिति)। Admin → टेस्ट कैलेंडर से संशोधित फ़ाइल इम्पोर्ट हो सकती है; दर्ज अंक नहीं बदलते। नए विषय की जगह अपने-आप विषय नहीं बनते (पहले Admin → विषय में जोड़ें)।

## 8. सुरक्षा

* पासवर्ड scrypt से hash; सेशन कुकी `HttpOnly + SameSite=Lax (+ Secure)`, पासवर्ड बदलते ही पुराने सत्र बंद।
* हर API पर सर्वर-स्तर की भूमिका जाँच (Admin/Teacher/Student); Teacher सिर्फ़ सौंपे विषय, Student सिर्फ़ अपना डेटा।
* CSRF सुरक्षा (custom header + Origin जाँच), सख़्त CSP (कोई inline script नहीं), सभी SQL parameterized, सभी आउटपुट escape।
* लॉगिन पर rate-limit; सभी महत्वपूर्ण कार्य ऑडिट लॉग में।

## 9. Backup

* Render के **paid PostgreSQL** में रोज़ाना backup मिलते हैं; free में नहीं।
* अतिरिक्त: समय-समय पर Admin → विद्यार्थी → "Excel एक्सपोर्ट", Admin → टेस्ट कैलेंडर → "Excel डाउनलोड", और रिपोर्ट Excel में रखें।

## 10. अपने कंप्यूटर पर चलाना / टेस्ट

```bash
npm install

npm run check            # deploy-पूर्व जाँच (syntax, data, dependencies, logic tests)
npm test                 # पूरे टेस्ट (Node 22+: API टेस्ट SQLite पर भी चलते हैं)
npm run demo             # (Node 22+) बिना PostgreSQL के डेमो: http://127.0.0.1:3111  (admin / Admin@123)
```

## 11. ध्यान देने योग्य बातें

* यह कोड मेरे विकास-परिवेश में **इंटरनेट/PostgreSQL के बिना** जाँचा गया: 20 स्वचालित टेस्ट (logic + पूरा API, SQLite स्टैंड-इन पर) और असली ब्राउज़र में सभी पेज/फ़्लो पास हुए। **असली PostgreSQL और `exceljs` से पहली बार चलना Render पर ही होगा** — यदि पहले deploy में कोई त्रुटि दिखे तो Render **Logs** की पंक्ति भेज दें।
* Excel `.xlsx` इम्पोर्ट/एक्सपोर्ट `exceljs` से होता है (पुरानी `.xls` फ़ाइल सपोर्ट नहीं)।
* सत्र/कक्षा बदलने के बाद विश्लेषण चालू सत्र का दिखता है; पुराने सत्र का डेटा विद्यार्थी के इतिहास में सुरक्षित रहता है।
